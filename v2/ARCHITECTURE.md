# Структура

Правила, які тримають код від того, щоб зміна одного місця валила решту.
Їх мало навмисно — правило, якого не памʼятають, не діє.

```
src/
  app/        точка входу, збірка застосунку, глобальні стилі
  ui/         дизайн-система: Button, Panel, Screen, Mascot, MonoNote
  screens/    по теці на екран, усе своє всередині
  api/        єдине місце, що говорить із сервером
  types/      доменні типи, спільні для екранів
  lib/        чисті хелпери без React
```

---

## 1. Екран не вирішує, що буде далі

Екран приймає `onStart`, `onFinish`, `onOpenLesson` — і **повідомляє намір**.
Куди вести, вирішує `app/App.tsx`.

Тому переставити порядок екранів — це правка одного файлу, а не десяти.

```tsx
// так
<Welcome onStart={() => go('/courses')} />

// не так
const Welcome = () => { const nav = useNavigate(); ... nav('/courses') }
```

---

## 2. Стилі не пишуться інлайном

Кнопка живе в `ui/Button.tsx`. Панель — в `ui/Panel.tsx`. Кольори — в
`tailwind.config.js`.

У старому додатку стиль кнопки був повторений інлайном у сорока місцях, тому
змінити вигляд кнопок означало день роботи й гарантовано щось пропустити.
Якщо стиль трапляється **двічі** — він переїжджає в `ui/`.

---

## 3. Кольори завжди явні

`color` і `background` задаються завжди. Ніколи не покладатись на системні:
Android у темному режимі всередині Telegram підставляє свої, і виходить біле
на білому. Це вже траплялось — і в кнопках відповідей, і в полях конструктора.

---

## 4. Із сервером говорить тільки `api/`

Екран не викликає `fetch`. Він викликає функцію з `api/`.

`api/client.ts` **кидає виняток на будь-який не-2xx**. Це знімає цілий клас
падінь: тіло помилки — це обʼєкт, і обʼєкт, покладений у стан замість списку,
кидає на першому `.map` під час рендеру, знімає все дерево і лишає **білий
екран**. Тут помилку неможливо переплутати з даними.

---

## 5. Ідентичність приходить із сервера

Ніколи не зчитувати «хто я» на першому рендері й не класти в залежності хука.
У старому додатку `USER_ID` захоплювався, поки був ще запасним `demo-user`, і
**чотири сторінки** назавжди лишались із чужими даними.

Правило: ідентичність приходить із підпису запиту, сервер сам визначає
користувача. Фронт її не передає.

---

## 6. Порожній екран — це баг

Кожен стан має що показати: маскота, рядок пояснення й одну дію. Немає карток,
немає інтернету, впав рендер — усе одно щось на екрані.

`ErrorBoundary` стоїть у корені **з першого екрана**, а не додається потім.

---

## 7. Декор не ловить дотик

Усі фонові площини — `pointer-events-none`. Інакше скошений блок ловить
натискання поверх кнопки, і це майже неможливо знайти.

---

## 8. Мертвий код видаляється одразу

У старому додатку лежали компонент, який не імпортувався від дня створення,
дві сторінки-заглушки на вигаданих даних і покинута карта. Вони плутали при
кожному читанні коду.

Не «закоментувати на потім», а видалити. Git памʼятає.

---

## Куди що класти

| що додаєте | куди |
|---|---|
| новий екран | `screens/<назва>/` |
| частина екрана, що потрібна лише йому | поруч у тій же теці |
| щось, що знадобиться двом екранам | `ui/` або `lib/` |
| новий запит до сервера | `api/` |
| тип, який бачать кілька екранів | `types/` |
| колір, відступ, радіус | `tailwind.config.js` |
